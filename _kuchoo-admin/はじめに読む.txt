================================================================
　空調王｜元締めの道具　2026-09-12
================================================================

ここは BIGBOSS の手元だけで動かす道具です。サイトには出ません。

やることは2つだけ。
　・空調王の本体をクラウドに載せる（版を上げるたび）
　・ライセンスキーを配る／期限を延ばす／止める


----------------------------------------------------------------
■ 最初の1回だけ（10分）
----------------------------------------------------------------

【1】クラウドに書き込むための鍵をもらう

　1. https://console.firebase.google.com/ を開く
　2. プロジェクト「airtec-sync」を選ぶ
　3. 左上の歯車 →「プロジェクトの設定」
　4. 上のタブ「サービス アカウント」
　5. 下のほうの「新しい秘密鍵の生成」→「キーを生成」
　6. JSONファイルが落ちてくる
　7. そのファイルを、このフォルダに
　　　　service-account.json
　　という名前で置く（名前を変えてください）

　★ この JSON は、パスワードそのものです。
　　 人に見せない。メールで送らない。GitHubに上げない（.gitignore済み）。
　　 アスラーダも中身は見ません。


【2】クラウドの許可設定を貼り直す　★これを忘れると誰も開けません

　1. https://console.firebase.google.com/ → airtec-sync
　2. 左メニュー「Firestore Database」→ 上のタブ「ルール」
　3. いま出ている文字を全部消して、
　　　　asurada\tools\estimate\firestore.rules
　　の中身を丸ごと貼り付ける
　4. 「公開」を押す

　前と違うのは1行だけです（読める置き場所に lic と app を足しました）。
　貼っていないと、空調王の画面に
　　　「空調王の設定に直しが要ります。」
　と出ます。そう出たら、ここを忘れています。


----------------------------------------------------------------
■ ふだんの手順
----------------------------------------------------------------

【空調王を直したあと、みんなに届けるまで】

　1) cd asurada\tools\estimate
　   node build.mjs                  ← 本体を1本に固める
　2) cd ..\..\_kuchoo-admin
　   node admin.mjs publish          ← クラウドに載せる
　3) git push                        ← 入口（index.html）を配る

　※ 版番号は version.txt を書き換えるだけでよくなりました。
　　 build.mjs が index.html と app.js を機械的にそろえます。


【キーを配る】

　node admin.mjs issue "今野空調" 2027-03-31

　→ キーが1つ出ます。相手に伝えて、50airtec.com/m を開いてもらうだけ。
　　 会員登録もメールアドレスも要りません。


【期限を延ばす（入金を確認したら）】

　node admin.mjs renew 今野空調 2028-03-31

　相手の端末には、次にクラウドへつないだとき（最長30日）に届きます。


【止める】

　node admin.mjs revoke 今野空調

　相手の端末は、手元の控えが切れたところ（最長30日）で開かなくなります。
　すぐ止めたいときは　node admin.mjs publish --rotate
　（合鍵を作り直すので、契約中の人だけが新しい合鍵を受け取ります）


【いま誰に配っているか】

　node admin.mjs list

　契約中の社数と、月いくら・年いくらになるかも出ます。


【その人が本当に開けるか確かめる】

　node admin.mjs check ABCDE-FGHJK-LMNPQ-RSTUV

　お客さんと同じ順番でたどって、開けるかどうかを言います。


----------------------------------------------------------------
■ いちばん大事な順番
----------------------------------------------------------------

　鍵を入れた日に、自分が閉め出されないように。

　　① node build.mjs
　　② node admin.mjs publish
　　③ node admin.mjs issue "50Airtec" 2099-12-31     ← 自分のぶん
　　④ node admin.mjs issue "今野空調" 2027-03-31      ← いま使っている人
　　⑤ 自分と今野空調さんの端末で、キーを入れて開けることを確かめる
　　⑥ そこまで済んでから git push

　★ ⑤を飛ばさないでください。


----------------------------------------------------------------
■ licences.json を消さないこと
----------------------------------------------------------------

　誰にどのキーを渡したかは、このフォルダの licences.json に控えます。
　クラウドの札は**そのキーで暗号にしてある**ので、
　キーを無くすと、こちらからも読めなくなります。

　パソコンを替えるときは、このファイルも一緒に持っていってください。
　（.gitignore に入れてあるので、GitHubには上がりません）


----------------------------------------------------------------
■ 正直に言っておくこと
----------------------------------------------------------------

　・**詳しい人には破られます。** 一度画面が開けば、本体はその人の
　　ブラウザの中にあります。開発者ツールを知っていれば取り出せます。
　　この鍵の役目は泥棒を止めることではなく、
　　「うっかり払わずに使い続ける」を止めることです。そこは確実に止まります。

　・**キーを他社に又貸しされても、こちらでは分かりません。**
　　いまは対策を作っていません。

　・**止めても、お客さんのデータは消えません。**
　　単価も見積も写真も、その人のブラウザの中に残ります。
　　払い直せば、そのまま続きから使えます。
　　これは長所なので、そう説明してください。
